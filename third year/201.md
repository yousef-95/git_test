## تحليل الحدودية من الدرجة الثانية (Quadratic Factoring)

تحليل الحدودية من الدرجة الثانية إلى قوسين يعني تحويل المعادلة من الشكل العام $ax^2 + bx + c$ إلى شكل ضرب قوسين $(x+m)(x+n)$. هناك عدة طرق تعتمد على شكل المعادلة، وإليك شرح مبسط لأشهر الحالات.

  

### الحالة الأولى: عندما يكون معامل $x^2$ يساوي (1)

- **الشكل:** $x^2 + bx + c$
    
      
    
- هذه هي الحالة الأسهل، وتسمى طريقة **"البحث عن عددين"**.
    
      
    

#### القاعدة:

ابحث عن عددين:

  

1. حاصل ضربهما يساوي الرقم الأخير ($c$).
    
      
    
2. حاصل جمعهما يساوي الرقم الذي في الوسط ($b$).
    
      
    

#### مثال: حلل $x^2 + 5x + 6$

- نبحث عن عددين ضربهما $6$ ومجموعهما $5$.
    
      
    
- الأعداد التي ضربها $6$ هي: $(1 \times 6)$ و $(2 \times 3)$.
    
      
    
- أي منهما مجموعهما $5$؟ الإجابة هي $2$ و $3$.
    
      
    
- الحل مباشرة في قوسين: $(x + 2)(x + 3)$.
    
      
    

### الحالة الثانية: الفرق بين مربعين (حالة خاصة)

- **الشكل:** $x^2 - c^2$ (حدين فقط، وبينهما علامة طرح، وكلاهما مربع كامل).
    
      
    

#### القاعدة:

نفتح قوسين، واحد موجب وواحد سالب، ونأخذ الجذر التربيعي لكل حد.

  

- **القانون:** $a^2 - b^2 = (a - b)(a + b)$
    
      
    

#### مثال: حلل $x^2 - 16$

- الجذر التربيعي لـ $x^2$ هو $x$.
    
      
    
- الجذر التربيعي لـ $16$ هو $4$.
    
      
    
- الحل مباشرة في قوسين: $(x - 4)(x + 4)$.
    
      
    

### الحالة الثالثة: عندما يكون معامل $x^2$ أكبر من (1)

- **الشكل:** $ax^2 + bx + c$ (مثلاً: $2x^2 + 7x + 3$)
    
      
    
- هنا نستخدم طريقة تسمى **طريقة التقسيم (Grouping Method)** أو طريقة $ac$.
    
      
    

#### الخطوات:

1. اضرب الرقم الأول ($a$) في الرقم الأخير ($c$).
    
      
    
2. ابحث عن عددين ضربهما يساوي الناتج، ومجموعهما يساوي الرقم الأوسط ($b$).
    
      
    
3. استبدل الحد الأوسط بهذين العددين، ثم حلل بالتجميع.
    
      
    

#### مثال: حلل $2x^2 + 7x + 3$

1. نضرب $2 \times 3 = 6$.
    
      
    
2. نبحث عن عددين ضربهما $6$ ومجموعهما $7$ $\rightarrow$ هما $6$ و $1$.
    
      
    
3. نفك الـ $7x$ إلى $6x + 1x$:
    
      
    
    $$2x^2 + 6x + x + 3$$
    
4. نأخذ عامل مشترك من أول حدين وعامل مشترك من آخر حدين:
    
      
    
    $$2x(x + 3) + 1(x + 3)$$
    
5. الآن لدينا $(x + 3)$ مكرر، نأخذه كقوس أول، والباقي في القوس الثاني:
    
      
    - **الحل النهائي:** $(x + 3)(2x + 1)$
        
          
        

### ملخص سريع لاختيار الطريقة:

- **حدين وبينهما ناقص وكلاهما مربعات؟** $\rightarrow$ فرق بين مربعين $(x - a)(x + a)$.
    
      
    
- **ثلاث حدود ومعامل $x^2$ هو 1؟** $\rightarrow$ ابحث عن عددين ضربهما الأخير وجمعهما الأوسط.
    
      
    
- **ثلاث حدود ومعامل $x^2$ رقم آخر؟** $\rightarrow$ استخدم طريقة الضرب والتقسيم.
    
      
    
- **إذا عجزت تماماً عن التحليل؟** $\rightarrow$ استخدم القانون العام لإيجاد الجذور ثم تحويلها إلى أقواس.
    
      
    

## التعامل مع إشارات السالب

وجود إشارات السالب لا يغير الطريقة، لكنه يغير قواعد اللعبة في اختيار الأعداد. تذكر دائماً قواعد الإشارات الأساسية:

  

- $(+) \times (+) = (+)$
    
      
    
- $(- \times (-) = (+)$
    
      
    
- $(+) \times (-) = (-)$
    
      
    

### الحالة الأولى: الرقم الأخير موجب والوسط سالب ($x^2 - bx + c$)

إذا كان الرقم الأخير موجباً، فهذا يعني أن العددين لهما نفس الإشارة. وبما أن الرقم الأوسط سالب، إذن العددان يجب أن يكونا سالبين.

  

- **مثال:** حلل $x^2 - 7x + 10$
    
      
    
    1. نبحث عن عددين حاصل ضربهما $+10$ ومجموعهما $-7$.
        
          
        
    2. بما أن الضرب موجب والجمع سالب $\leftarrow$ (العددان سالبان).
        
          
        
    3. الأعداد التي ضربها $10$ هي: $(2, 5)$ أو $(1, 10)$.
        
          
        
    4. نجرب السالب: $(-2) + (-5) = -7$ (صحيح!).
        
          
        
    
    - **الحل:** $(x - 2)(x - 5)$
        
          
        

### الحالة الثانية: الرقم الأخير سالب ($x^2 \pm bx - c$)

إذا كان الرقم الأخير سالباً، فهذا يعني حتماً أن العددين مختلفان في الإشارة (واحد موجب وواحد سالب).

  

- **القاعدة:** العدد الأكبر يأخذ إشارة الرقم الأوسط.
    
      
    
- **مثال (أ): حلل $x^2 + 3x - 10$** (الوسط موجب)
    
      
    
    1. نبحث عن عددين ضربهما $-10$ ومجموعهما $+3$.
        
          
        
    2. ضرب سالب $\leftarrow$ (واحد موجب وواحد سالب).
        
          
        
    3. الأعداد هي $5$ و $2$. لكي يكون المجموع $+3$، يجب أن يكون الكبير موجباً: $(+5) + (-2) = +3$.
        
          
        
    
    - **الحل:** $(x + 5)(x - 2)$
        
          
        
- **مثال (ب): حلل $x^2 - 3x - 10$** (الوسط سالب)
    
      
    
    1. نبحث عن عددين ضربهما $-10$ ومجموعهما $-3$.
        
          
        
    2. لكي يكون المجموع $-3$، يجب أن يكون الكبير سالباً: $(-5) + (+2) = -3$.
        
          
        
    
    - **الحل:** $(x - 5)(x + 2)$
        
          
        

### الحالة الثالثة: إذا كانت $x^2$ مسبوقة بسالب ($-x^2 + bx + c$)

إذا بدأت المعادلة بسالب، فإن أسهل طريقة هي أخذ $(-1)$ كعامل مشترك من المعادلة كلها لقلب جميع الإشارات، ثم التحليل بشكل طبيعي.

  

- **مثال:** حلل $-x^2 + 5x - 6$
    
      
    
    1. نخرج السالب خارج قوس كبير: $-(x^2 - 5x + 6)$
        
          
        
    2. نحلل ما بداخل القوس $(x^2 - 5x + 6)$ بطريقة الحالة الأولى: عددين ضربهما $+6$ وجمعهما $-5$ $\rightarrow$ هما $-2$ و $-3$.
        
          
        
    3. نضع الحل داخل القوس مع الإبقاء على السالب في الخارج.
        
          
        
    
    - **الحل:** $-(x - 2)(x - 3)$

## 2. Mathematical Induction

Mathematical Induction is like a row of falling dominoes. If you can push the first one, and you can prove that any falling domino will knock over the next one, then all the dominoes will eventually fall.

  

### The 3-Step Process:

1. **Base Case:** Prove the statement is true for the first possible value (usually $n=1$).
    
      
    
2. **Inductive Hypothesis:** Assume the statement is true for some arbitrary integer $k$. (You just write the formula replacing $n$ with $k$).
    
      
    
3. **Inductive Step:** Prove that if the statement is true for $k$, it must be true for $k+1$. This is where the actual algebra happens.
    
      
    

## 3. Induction Proof (Example)

Since "Induction Proof" is simply the application of "Mathematical Induction," let's do a full step-by-step proof.

  

### Problem:

Prove that for all $n \ge 1$:

  

$$1 + 2 + 3 + \dots + n = \frac{n(n+1)}{2}$$

#### Step 1: Base Case ($n=1$)

- **Left Hand Side (LHS):** $1$
    
      
    
- **Right Hand Side (RHS):**
    
      
    
    $$\frac{1(1+1)}{2} = \frac{2}{2} = 1$$
    
- $\text{LHS} = \text{RHS}$. The base case holds.
    
      
    

#### Step 2: Inductive Hypothesis

Assume the statement is true for $n=k$:

  

$$1 + 2 + 3 + \dots + k = \frac{k(k+1)}{2}$$

#### Step 3: Inductive Step

We must prove it is true for $n = k+1$. That means we want to show that:

  

$$1 + 2 + 3 + \dots + k + (k+1) = \frac{(k+1)((k+1)+1)}{2} = \frac{(k+1)(k+2)}{2}$$

**The Proof:** Start with the LHS of the $k+1$ equation:

  

$$(1 + 2 + 3 + \dots + k) + (k+1)$$

Substitute the Inductive Hypothesis (the part in the parentheses):

  

$$\frac{k(k+1)}{2} + (k+1)$$

Now, use algebra to combine them (find a common denominator):

  

$$= \frac{k(k+1) + 2(k+1)}{2}$$

Factor out $(k+1)$:

  

$$= \frac{(k+1)(k+2)}{2}$$

$\text{LHS} = \text{RHS}$. The proof is complete!

To prove this using mathematical induction, we need to show that the sum of the function $Q(i)$ from $i=1$ to $n$ equals the formula $n^2(n-1)$.

  

### The Problem:

Prove that $\sum_{i=1}^{n}(3i^2 - 5i + 2) = n^2(n-1)$ for all $n \ge 1$.

  

### Step 1: Base Case ($n=1$)

We must check if the formula holds true for the first term.

  

- **Left Hand Side (LHS):** Calculate $Q(1)$
    
      
    
    $$Q(1) = 3(1)^2 - 5(1) + 2 = 3 - 5 + 2 = 0$$
    
- **Right Hand Side (RHS):** Plug $n=1$ into the formula $n^2(n-1)$
    
      
    
    $$1^2(1-1) = 1(0) = 0$$
    

$\text{LHS} = \text{RHS}$. The base case is true.

  

### Step 2: Inductive Hypothesis

We assume the statement is true for some arbitrary integer $k$. This means we assume:

  

$$\sum_{i=1}^{k}(3i^2 - 5i + 2) = k^2(k-1)$$

### Step 3: Inductive Step

We must now prove that the statement is true for $n = k+1$.

  

Our goal is to show that:

  

$$\sum_{i=1}^{k+1} Q(i) = (k+1)^2((k+1)-1) = (k+1)^2(k)$$

#### The Proof:

The sum up to $k+1$ is equal to the sum up to $k$ plus the next term $Q(k+1)$:

  

$$\sum_{i=1}^{k+1} Q(i) = \left[\sum_{i=1}^{k} Q(i)\right] + Q(k+1)$$

1. **Substitute the Inductive Hypothesis for the first part and the formula for $Q(k+1)$:**
    
      
    
    $$= [k^2(k-1)] + [3(k+1)^2 - 5(k+1) + 2]$$
    
2. **Simplify the term $Q(k+1)$:**
    
      
    
    $$3(k^2 + 2k + 1) - 5k - 5 + 2$$
    
    $$= 3k^2 + 6k + 3 - 5k - 3$$
    
    $$= 3k^2 + k$$
    
3. **Combine the whole expression:**
    
      
    
    $$= k^2(k-1) + (3k^2 + k)$$
    
    $$= k^3 - k^2 + 3k^2 + k$$
    
    $$= k^3 + 2k^2 + k$$
    
4. **Factor out $k$ from the expression:**
    
      
    
    $$= k(k^2 + 2k + 1)$$
    
    $$= k(k+1)^2$$
    

This is exactly the goal we were aiming for!

  

$$\text{LHS} = \text{RHS}$$

### Final Conclusion:

Since the base case $n=1$ is true, and we have proved that if the statement is true for $n=k$ it must also be true for $n=k+1$, by the principle of **Mathematical Induction**, the statement is true for all $n \ge 1$.


## Merge sort :
## 🧩 Merge Sort: The Complete Summary

### 1. What is Merge Sort?

Merge Sort is a **Divide and Conquer** sorting algorithm. It works by recursively breaking down a list into several sub-lists until each sub-list consists of a single element, then merging those sub-lists in a manner that results in a sorted list.

  

### 2. How it Works (The 3-Step Process)

The algorithm follows three main phases:

  

1. **Divide:** Split the unsorted list into two halves at the middle index $m$.
    
      
    
2. **Conquer:** Recursively call `mergesort` on the left half and the right half.
    
      
    - **Base Case:** When the list size becomes $1$, it is considered sorted.
        
          
        
3. **Combine (The Merge):** Use a `merge()` function to take two sorted sub-lists and combine them into one larger sorted list by comparing the front elements of each.
    
      
    

### 3. Mathematical Analysis (The "Why")

#### A. The Recurrence Relation

The time complexity is represented by the formula:

  

$$T(n) = 2T(n/2) + n$$

- **$2T(n/2)$:** We split the problem into $2$ sub-problems of half the size.
    
      
    
- **$n$:** The time it takes to merge the two halves (linear time).
    
      
    

#### B. Solving with Master Theorem

Using the Master Theorem $T(n) = aT(n/b) + f(n)$:

  

- $a = 2$, $b = 2$, $f(n) = n$
    
      
    
- **Critical Value:** $n^{\log_b a} = n^{\log_2 2} = n^1 = n$
    
      
    
- Since $f(n) = n$, this is **Case 2**.
    
      
    
- **Total Complexity:** $\Theta(n \log n)$
    
      
    

### 4. Complexity Cheat Sheet

|**Complexity**|**Notation**|**Reason**|
|---|---|---|
|**Best Case Time**|$\Omega(n \log n)$|Even if sorted, it still divides and merges.|
|**Average Case Time**|$\Theta(n \log n)$|Consistent performance.|
|**Worst Case Time**|$O(n \log n)$|No "worst-case" input like in QuickSort.|
|**Space Complexity**|$O(n)$|Requires a temporary array (`tmp`) to merge.|
|**Stability**|**Stable**|Maintains the relative order of equal elements.|

### 5. Pros and Cons

#### ✅ Pros:

- **Predictable:** Always runs in $O(n \log n)$ regardless of whether the input is sorted, reverse-sorted, or random.
    
      
    
- **Stable:** Great for sorting objects where the original order of equal items must be preserved.
    
      
    
- **Efficient for Large Data:** Much faster than Bubble, Insertion, or Selection sort for large datasets.
    
      
    

#### ❌ Cons:

- **Memory Heavy:** Unlike QuickSort (which sorts "in-place"), Merge Sort needs extra space $O(n)$ for the temporary array.
    
      
    
- **Overkill for Small Data:** For very small arrays, simple algorithms like Insertion Sort can actually be faster.
    

### 🚀 Final Logic Flow (For your Code)

$$\text{Main Array} \longrightarrow \text{Divide} \longrightarrow \text{Left Half } \vert \text{ Right Half} \longrightarrow \text{Divide} \longrightarrow \dots \longrightarrow \text{Base Case (Single Elements)}$$

$$\Downarrow$$

$$\text{Single Elements} \longrightarrow \text{Merge} \longrightarrow \text{Sorted Pairs} \longrightarrow \text{Merge} \longrightarrow \text{Sorted Quads} \longrightarrow \text{Merge} \longrightarrow \text{Fully Sorted Array}$$


## E8 — Proving Bounds for Oscillating Functions (Pages 20–21)

In this example, we address a common challenge in complexity analysis: proving an upper bound for a function that oscillates (moves up and down) rather than growing monotonically.

  

### 1. The Goal (Page 20)

We want to prove that the function:

  

$$f(n) = n(\sin n + 1)$$

is $O(n)$.

  

If we were to look at a graph of this function, we would see a series of peaks and valleys. Because the function doesn't move in a straight line, we cannot simply "pick a large $n$" to see where it goes; we must find a **mathematical envelope** that the function can never exceed.

  

### 2. The Proof by Inequality (Page 20)

To prove $f(n) \in O(n)$, we must find constants $c > 0$ and $n_0 \in \mathbb{N}$ such that:

  

$$f(n) \le c \cdot n \quad \text{for all } n \ge n_0$$

#### Step 1: Analyze the oscillating term

We know from trigonometry that the sine function is bounded:

  

$$-1 \le \sin(n) \le 1$$

#### Step 2: Shift the bound

By adding $1$ to all parts of the inequality, we find the range of the term inside the parentheses:

  

$$0 \le \sin(n) + 1 \le 2$$

#### Step 3: Apply the multiplier $n$

For all $n \ge 1$, we multiply the inequality by $n$:

  

$$0 \le n(\sin(n) + 1) \le 2n$$

#### Conclusion:

By choosing $c = 2$ and $n_0 = 1$, we have satisfied the formal definition of Big-O:

  

$$f(n) \le 2n \quad \text{for all } n \ge 1$$

Therefore, $f(n) \in O(n)$.

  

### 3. Witness Constants and "Tightness" (Page 21)

Page 21 clarifies an important property of Big-O: it is an upper bound, not necessarily a tight one.

  

- **The Tightest Bound:** In this case, $c = 2$ is the "tightest" witness because the peaks of the function exactly touch the line $2n$.
    
      
    
- **Valid but Loose Bounds:** Another upper bound such as $2.5n$ also works. Because $f(n) \le 2n$, it is mathematically true that $f(n) \le 2.5n$ as well.
    
      
    
- **The Takeaway:** Both $c = 2$ and $c = 2.5$ are valid witnesses. A proof is valid as long as the inequality holds, regardless of whether there is a smaller $c$ that also works.
    
      
    

> **Instructor Aside:** Note the warning on page 21: _"Sampling a graph alone cannot prove it for every large $n$."_ In a formal exam or paper, you must provide the algebraic inequality (the "envelope" logic) rather than just pointing to a plot, because a graph only shows a finite set of points, whereas Big-O describes the behavior for all $n$ beyond $n_0$.


## Recurrence Relations: Binary Search (Slide 1)

When an algorithm is recursive, we cannot simply count loops. Instead, we write a **recurrence relation**: an equation that defines the running time of a problem of size $n$ in terms of the running time of smaller versions of the same problem.

  

### The Logic

In the provided `contains` function (Binary Search):

  

- **The Divide Step:** The algorithm calculates a midpoint and compares the target. This takes constant time, $\Theta(1)$.
    
      
    
- **The Conquer Step:** Based on the comparison, the algorithm makes **exactly one** recursive call to either the left half `[lo, mid]` or the right half `[mid + 1, hi]`.
    
      
    
- **Problem Reduction:** Each call reduces the search interval by half.
    
      
    

### The Recurrence

The worst-case time $T(n)$ can be expressed as:

  

$$T(n) = T(\lfloor n/2 \rfloor) + \Theta(1)$$

- **$T(\lfloor n/2 \rfloor)$:** The cost of the single recursive call on half the data.
    
      
    
- **$\Theta(1)$:** The constant work done at the current level (calculating `mid`, performing comparisons).
    
      
    

**Result:** As noted on the slide, using the Master Theorem (specifically Case 2), this recurrence solves to **$\Theta(\log n)$**.

  

## Limitations of the Master Theorem (Slide 2)

The Master Theorem is a "shortcut" for solving recurrences of the form $T(n) = aT(n/b) + f(n)$. However, it is not universal. The slide highlights four critical "failure points":

  

1. **Recursive sizes do not fit:** The Master Theorem requires subproblems to be a constant fraction of the original ($n/b$).
    
      
    - _Example:_ $T(n) = T(n-1) + 1$. This is linear reduction, not fractional. The Master Theorem cannot be used here.
        
          
        
2. **Non-constant number of calls:** The value $a$ (number of recursive calls) must be a constant.
    
      
    - _Example:_ $T(n) = nT(n/2) + n$. Here, the number of calls $n$ changes as the input grows.
        
          
        
3. **Gaps in the Cases:** Sometimes the function $f(n)$ doesn't fit perfectly into Case 1, 2, or 3.
    
      
    - _Example:_ $T(n) = 2T(n/2) + n/\log n$. The $n/\log n$ term is "too small" for Case 3 but "too large" for Case 2.
        
          
        
4. **Alternative Methods:** When the Master Theorem fails, we must use:
    
      
    - **Expansion/Iteration:** Unrolling the recurrence manually.
        
          
        
    - **Recursion Trees:** Drawing the calls to visualize the work per level.
        
          
        
    - **Substitution Method:** Guessing the answer and proving it via induction.
        
          
        

## Recursive Time vs. Auxiliary Space (Slide 3)

This is a crucial distinction in CS. Time is cumulative; space is "peak usage."

  

### 1. Time Complexity (Cumulative)

"Time counts all work." Every single operation performed in every single recursive call is added to the total. If a recursion tree has 1,000 nodes, and each node does 1 unit of work, the total time is 1,000 units.

  

### 2. Auxiliary Space Complexity (Peak)

"Stack space counts live calls." Recursive functions use the Call Stack. A function only occupies space on the stack while it is active (waiting for its children to return).

  

- Once a recursive call returns, its stack frame is popped and the space is reclaimed.
    
      
    
- Therefore, the auxiliary space is determined by the **maximum depth** of the recursion tree, not the total number of calls.
    

### 3. Comparison Examples

| **Algorithm**     | **Time Complexity** | **Stack Space**  | **Total Aux Space** | **Note**                                                                                                                                                     |
| ----------------- | ------------------- | ---------------- | ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Binary Search** | $\Theta(\log n)$    | $\Theta(\log n)$ | $\Theta(\log n)$    | The recursion depth is $\log n$. Iterative versions can reduce this to $O(1)$.                                                                               |
| **Merge Sort**    | $\Theta(n \log n)$  | $\Theta(\log n)$ | $\Theta(n)$         | The stack depth is $\log n$, but the "merge" step requires a temporary array of size $n$. The $\Theta(n)$ merge buffer dominates the $\Theta(\log n)$ stack. |

|**Deletion**|Head|$O(1)$|Simply move `head` to `head->next`.|
|**Deletion**|Tail|$O(n)$|**The Problem Case:** Must scan from head to find the predecessor to set its `next` to `nullptr`.|
|**Search**|Any|$O(n)$|Linear scan; ends when `tmp == nullptr`.|

- **Boundary Cases:**
    
      
    - **Empty List:** Head and tail are both `nullptr`.
        
          
        

## 2. Doubly Linked List (DLL)

**Focus:** Two-way traversal.

  

- **Operational Cases:**
    
      
    - **Insertion at Tail ($O(1)$):** Create node $\rightarrow$ set `node->next = nullptr` $\rightarrow$ set `node->prev = oldTail` $\rightarrow$ update `tail = node` $\rightarrow$ update `oldTail->next = node`.
        
          
        
    - **Deletion from Tail ($O(1)$):** Access predecessor directly via `tail->prev` $\rightarrow$ move `tail` pointer to this predecessor $\rightarrow$ set `newTail->next = nullptr`.
        
          
        
    - **Deletion of Middle Node ($O(1)$):** If node `p` is known: `p->prev->next = p->next` **AND** `p->next->prev = p->prev`.
        
          
        
    - **Search ($O(n)$):** Linear scan in either direction.
        
          
        
- **Boundary Cases:**
    
      
    - **Empty State:** Both head and tail are `nullptr`.
        
          
        
    - **Single Node:** Head and tail point to the same node; both `prev` and `next` are `nullptr`.
        
          
        
    - **After Deleting Only Node:** Both head and tail must be reset to `nullptr` to avoid dangling pointers.
        
          
        

## 3. Circular Singly Linked List (CLL)

**Focus:** The "Ring" structure.

  

- **Operational Cases:**
    
      
    - **Insertion at Tail ($O(1)$):** New node points to the head (`tail->next`) $\rightarrow$ old tail points to new node $\rightarrow$ `tail` pointer advances to the new node.
        
          
        
    - **Insertion at Head ($O(1)$):** New node points to the head (`tail->next`) $\rightarrow$ old tail points to new node $\rightarrow$ **Crucial:** `tail` pointer does **not** move.
        
          
        
    - **Deletion from Head ($O(1)$):** Use `tail->next` to identify the head $\rightarrow$ bypass the first node: `tail->next = first->next`.
        
          
        
    - **Deletion from Tail ($O(n)$):** **The Problem Case:** Even in a ring, you cannot go backward. You must scan the entire ring to find the node before the tail.
        
          
        
    - **Search ($O(n)$):** Requires a `do-while` loop. Starts at the head and stops when the pointer returns to the start node.
        
          
        
- **Boundary Cases:**
    
      
    - **Empty Ring:** `tail == nullptr`.
        
          
        
    - **One-Node Ring:** `tail->next == tail` (the node points to itself).
        
          
        
    - **Search for Missing Value:** The pointer visits every node exactly once, returns to the start node, and returns `false`.
        

## Summary Table: The "Delete Tail" Comparison

| **Representation** | **Delete Tail Complexity** | **Reason**                                     |
| ------------------ | -------------------------- | ---------------------------------------------- |
| **SLL**            | $O(n)$                     | Must scan for predecessor.                     |
| **DLL**            | $O(1)$                     | Has a direct `prev` pointer.                   |
| **CLL (Singly)**   | $O(n)$                     | Must scan for predecessor (no backward links). |
| **CLL (Doubly)**   | $O(1)$                     | Has `prev` and wraparound capability.          |

# Queue :
## C4 — Queue Representation Strategies (Page 10)

The fundamental challenge of implementing a Queue is maintaining a First-In, First-Out (FIFO) behavior efficiently. While a stack only needs to be efficient at one end, a queue must be efficient at both the rear (for enqueue) and the front (for dequeue).

  

The slides outline three primary strategies for representing a queue:

  

### 1. The Simple Array (The Inefficient Way)

In a basic linear array, if you dequeue the element at index 0, you are left with an unused position at the front. To keep the front of the queue at index 0, you would have to shift every remaining element one position to the left.

  

- **Cost:** This shifting operation takes $O(n)$ time — p10.
    
      
    
- **Verdict:** This is unacceptable for high-performance applications.
    
      
    

### 2. The Circular Array (The Space-Efficient Way)

To avoid the $O(n)$ shift, we use a Circular Array. Instead of shifting elements, we move the "front" index forward. When the "rear" index reaches the end of the array, it "wraps around" to the beginning of the array (provided there is empty space created by previous dequeue operations).

  

- **Benefit:** This allows both enqueue and dequeue to remain $O(1)$ while reusing the fixed storage space — p10.
    
      
    

### 3. Linked Structures (The Dynamic Way)

Linked lists are naturally suited for queues because they allow $O(1)$ insertions and deletions at the endpoints. According to Page 10, the following suffice:

  

- **Singly Linked List with head AND tail:** enqueue at the tail, dequeue at the head.
    
      
    
- **Doubly Linked List:** Provides maximum flexibility for endpoint operations.
    
      
    
- **Circular Linked List:** As seen later in the lecture, using a `lastNode` pointer allows $O(1)$ access to both the rear (`lastNode`) and the front (`lastNode->next`).

## Deep Dive: The Array as a "Sliding Window"

To explain this more deeply, you have to think of the array as a fixed piece of land, and the Queue as a "sliding window" moving across that land.

  

In a basic array implementation of a queue, we use two variables (indices) to keep track of the boundaries:

  

1. `first` (or front): The index of the oldest item (the one that will be dequeued next).
    
      
    
2. `storage` (or rear): The index where the next new item will be placed.
    
      
    

### Step-by-Step Logic in Example E4(b)

#### Step 1: The Filling Phase

Imagine an array of size 10. Initially, `first = 0` and `storage = 0`.

  

- $\text{enqueue(10)}$: We put 10 at index 0. Then we move `storage` to 1.
    
      
    
- $\text{enqueue(5)}$: We put 5 at index 1. Then we move `storage` to 2.
    
      
    
- **Current State:** $[10, 5, \_, \_, \dots] \rightarrow \text{first is at 0, storage is at 2.}$
    
      
    

#### Step 2: The Dequeue (Creating the "Gap")

Now, we call $\text{dequeue()}$. According to the FIFO rule, we must remove the oldest item, which is at `first` (index 0).

  

The critical decision: Do we slide the remaining items forward?

  

- **Option A (Shifting):** Move 5 from index 1 to index 0. This keeps the queue at the start of the array, but if you have 1,000 items, you have to perform 999 moves. This is $O(n)$ time and is very slow.
    
      
    
- **Option B (Indexing):** We leave 5 exactly where it is and simply change the `first` index. We say: "The queue no longer starts at 0; it now starts at 1."
    
      
    
- **Current State:** $[(\text{empty}), 5, \_, \_, \dots] \rightarrow \text{first is now 1, storage is still 2.}$
    
      
    

This is the **"Gap."** Index 0 is now a "dead zone." It contains a value, but the queue has "forgotten" it because the first pointer has moved past it.

  

#### Step 3: The "Crawling" Problem

As you continue to enqueue and dequeue, the "window" of active data crawls toward the end of the array.

  

If we $\text{enqueue(15)}$ and $\text{enqueue(7)}$, the array looks like this:$[(\text{empty}), 5, 15, 7, \_, \dots] \rightarrow \text{first} = 1, \text{storage} = 4$.

  

### The Crisis

What happens when the storage index hits the very last slot of the array (e.g., index 99)?

  

Even if the first index is at 90 (meaning indices 0 through 89 are all empty "gaps"), the computer will throw an Overflow Error. It thinks the array is full because `storage` has reached the end, even though 90% of the array is actually empty!

  

## How the "Circular Array" (C4) Fixes This

To stop the queue from "crawling" off the end of the array, we use the Modulo Operator ($\%$).

  

Instead of just doing $\text{storage} = \text{storage} + 1$, we do:

  

$$\text{storage} = (\text{storage} + 1) \pmod{\text{Capacity}}$$

### What This Does Visually

When `storage` reaches the last index (e.g., 99) and you enqueue another item, the modulo operator wraps it back around to index 0.

  

If the first pointer has moved forward (leaving gaps at the beginning), the storage pointer simply circles back and fills those gaps. This turns the linear array into a virtual ring, allowing us to use the space infinitely without ever needing to shift elements ($O(1)$ time).



# Deque :
## C3 — Priority Queue Implementations & Costs (Pages 5–6)

Unlike a standard FIFO queue, a Priority Queue serves elements based on their assigned priority. The goal is to maintain this ordering while keeping insertion and removal efficient — p2.

  

There are three primary ways to implement this, each shifting the "cost" between the enqueue and dequeue operations:

  

### 1. Unsorted List

In this approach, we don't care about the order when adding items.

  

- **Enqueue:** Simply add the item to the end of the list. **Cost:** $O(1)$ — p5.
    
      
    
- **Dequeue Highest:** Since the list is unsorted, you must scan every single element to find the one with the maximum priority. **Cost:** $O(n)$ — p5.
    
      
    

### 2. Array-Based Sorted List

Here, we maintain the array in sorted order. The slides suggest keeping the highest priority last.

  

- **Dequeue Highest:** Since the highest priority is at the end, removal is a simple index operation. **Cost:** $O(1)$ — p5.
    
      
    
- **Enqueue:** We can use binary search to find the correct insertion spot in $O(\log n)$, but we must then shift all elements to the right to make room. **Cost:** $O(n)$ — p5.
    
      
    

### 3. Linked Sorted List (Largest to Smallest)

In this version, the list is sorted such that the highest priority is always at the head.

  

- **Dequeue Highest:** Simply remove the head node. **Cost:** $O(1)$ — p5.
    
      
    
- **Enqueue:** You must traverse the list linearly to find the correct spot to insert the new node to maintain the sorted order. **Cost:** $O(n)$ — p5.
    
      
    

### Summary of Costs — p6

|**Representation**|**Enqueue**|**Dequeue highest**|**Inspect highest**|
|---|---|---|---|
|**Unsorted linked list + tail**|$O(1)$|$O(n)$|$O(n)$|
|**Sorted array, highest last**|$O(n)$|$O(1)$|$O(1)$|
|**Sorted linked list, highest first**|$O(n)$|$O(1)$|$O(1)$|

## C4 — Deque (Double-Ended Queue) Definition (Page 7)

A **Deque** (pronounced "deck") is a linear structure that generalizes the queue. While a standard queue restricts you to one end for entry and the other for exit, a deque allows additions and removals at both the front and the back — p7.

  

### Implementation Options Mentioned on Page 7

1. **Doubly Linked List:** A `std::list` in C++ is a perfect candidate because it already provides $O(1)$ operations at both ends.
    
      
    
2. **The `std::deque`:** A specialized C++ STL container designed specifically for this purpose.
    
      
    

## C5 — C++ `std::deque` Properties (Page 8)

The `std::deque` is more powerful than a simple linked list because it combines the benefits of arrays and lists.

  

### Key Performance Characteristics — p8

- **Random Access:** Unlike `std::list`, you can access any element by index (e.g., `d[i]`) in $O(1)$ time.
    
      
    
- **Endpoint Operations:** `push_front`, `push_back`, `pop_front`, and `pop_back` all operate in $O(1)$ time.
    
      
    
- **Middle Operations:** Inserting or erasing elements in the middle of the deque is expensive, taking $O(n)$ in the worst case.
    
      
    

### Internal Representation — p8

> **Instructor aside:** You might wonder how it achieves both $O(1)$ indexing and $O(1)$ endpoint growth. Unlike a `std::vector`, which is one single contiguous block of memory, `std::deque` is typically implemented as a sequence of fixed-size blocks (chunks). As the deque grows, it allocates new blocks. A "map" (another array) keeps track of where these blocks are. This is why the slide notes: "Contiguous storage is not guaranteed" — p8.
> 
>   

## 1. Accessing is Just Math ($O(1)$)

When the slides say you have $O(1)$ random access, it means the computer can calculate the exact memory address of `d[i]` almost instantly.

  

Because the `std::deque` uses blocks of memory, it doesn't have to "walk" through the list. It uses a simple formula:

  

$$\text{Address} = (\text{Block Map}[\text{index} / \text{block\_size}]) + (\text{index} \% \text{block\_size})$$

This calculation takes the same amount of time whether the index is 5 or 5 million. That is why reading or updating a value at a specific index is $O(1)$.

  

## 2. Inserting/Erasing is About Shifting ($O(n)$)

Inserting a new element is not just about finding a spot; it is about making room for that element.

  

Imagine a row of people sitting in fixed chairs. You want to insert a new person into the 5th chair. Even though you can point to the 5th chair instantly ($O(1)$ access), you cannot simply "overlap" the new person onto the person already sitting there.

  

To make room, every single person from the 5th chair to the end of the row must stand up and move one chair to the right.

  

In a `std::deque`:

  

- If you insert at index $i$, the deque must shift all elements from $i$ to the end one position to the right.
    
      
    
- If you erase at index $i$, the deque must shift all elements to the right of $i$ one position to the left to fill the gap.
    
      
    

In the worst case (inserting near the middle), you might have to move $n/2$ elements. In Big-O notation, we ignore the constant $1/2$, so this is $O(n)$.

  

## Summary Comparison

|**Operation**|**Complexity**|**What the computer does**|
|---|---|---|
|**Access `d[i]`**|$O(1)$|Does a quick math calculation to find the address.|
|**Update `d[i] = x`**|$O(1)$|Finds the address ($O(1)$) and overwrites the value.|
|**Insert/Erase**|$O(n)$|Finds the address ($O(1)$) **BUT** then moves thousands of other elements to make/fill space.|

> **Instructor aside:** The C++ `std::deque` is actually slightly smarter than a `std::vector`. If you insert near the front, it shifts elements to the left; if you insert near the back, it shifts elements to the right. It always picks the shorter path. However, if you insert exactly in the middle, it still has to move half the container, which is still mathematically $O(n)$.

# Priority Queue :

## C9 — `std::priority_queue` STL Details (Pages 21–23)

While we discussed basic implementations of priority queues in C3, the C++ Standard Template Library (STL) provides a highly optimized version: `std::priority_queue`.

  

### 1. The Underlying Mechanism

The STL `priority_queue` is a container adaptor. By default, it uses a `std::vector` for storage. However, it does not simply keep a sorted list. Instead, it maintains a **heap ordering**.

  

- **Crucial Detail:** The underlying vector is not fully sorted. It only guarantees that the element with the highest priority is always at the "top" (the root of the heap).
    
      
    

### 2. Controlling Priority (Max-Heap vs. Min-Heap)

You can change which value is considered "highest priority" by changing the comparator:

  

- **Default (`std::less`):** The largest value has the highest priority. This is a **Max-Heap**.
    
      
    
- **Reverse (`std::greater`):** The smallest value has the highest priority. This is a **Min-Heap**.
    
      
    

### 3. Performance Guarantees

Because it uses a heap structure, the costs are significantly better than the $O(n)$ costs we saw in C3:

  

- **`top()`:** $O(1)$. The highest priority item is always immediately accessible.
    
      
    
- **`push()` and `pop()`:** $O(\log n)$. When you add or remove an element, the heap must "re-adjust" (bubble up or trickle down), which takes logarithmic time.
    
      
    

### 4. Important Constraints

- **Ties:** If two items have the same priority, the STL does not guarantee FIFO order. If you need to preserve arrival order for ties, you must encode the arrival time into the priority value.
    
      
    
- **No Random Access:** You cannot access elements in the middle, update a key, or erase an arbitrary element. You can only interact with the `top()`.
    
      
    
- **Read-only Behavior:** Unlike some other STL containers, `top()` in a priority queue does not provide a mutable reference — p23. You must read the value, then `pop()` it if you wish to remove it.

    - The largest value is treated as the highest priority.

2. **Min-Heap Ordering (`std::greater<int>`):**

## Deep Dive: Understanding Example E4

To understand Example E4, you first have to understand how `std::priority_queue` works under the hood. Unlike a regular queue, it does not store elements in a simple line; it organizes them into a Heap (a specialized tree structure).

  

### 1. `pq1` (The Default Max-Heap)

- **Code:** `priority_queue<int> pq1;`
    
      
    
- **Logic:** In C++, the default comparator is `std::less`. In the context of a priority queue, this means "if A is less than B, A has lower priority." Therefore, the largest value is always kept at the top.
    
      
    
- **Input:** `3, 1, 2`
    
      
    
- **Heap Organization:** The heap ensures 3 (the max) is at the root.
    
      
    
- **Extraction:**
    
      
    1. `top()` is 3. Pop it.
        
          
        
    2. Heap re-adjusts. The next largest is 2. Pop it.
        
          
        
    3. Only 1 remains. Pop it.
        
          
        
- **Output:** `3 2 1`
    
      
    

### 2. `pq2` (The Min-Heap)

- **Code:** `priority_queue<int, vector<int>, greater<int>> pq2;`
    
      
    
- **Logic:** By passing `std::greater<int>`, we flip the priority logic. Now, the "greater" the value, the "lower" its priority. This creates a Min-Heap, where the smallest value is always at the top.
    
      
    
- **Input:** `3, 1, 2`
    
      
    
- **Heap Organization:** The heap ensures 1 (the min) is at the root.
    
      
    
- **Extraction:**
    
      
    1. `top()` is 1. Pop it.
        
          
        
    2. Heap re-adjusts. The next smallest is 2. Pop it.
        
          
        
    3. Only 3 remains. Pop it.
        
          
        
- **Output:** `1 2 3`
    
      
    

### 3. `pq3` (Range Construction)

- **Code:**
    
      
    
    C++
    
    ```
    int a[] = {4, 6, 5};
    priority_queue<int> pq3(a, a + 3);
    ```
    
- **Logic:** This is the most interesting part of the example because it uses Range Construction. Instead of calling `push()` three times, you pass a pointer to the start (`a`) and the end (`a + 3`) of an existing array.
    
      
    
- **How it works internally:** When you use this constructor, C++ does not just copy the array. It performs an operation called **Heapify** (specifically using `std::make_heap`).
    
      
    1. **The Input:** The array is `{4, 6, 5}`.
        
          
        
    2. **Heapification:** The algorithm rearranges these elements in the underlying vector to satisfy the heap property. Since `pq3` uses the default `std::less` (Max-Heap), it ensures the largest element (`6`) is moved to the root position.
        
          
        
    3. **The Resulting State:** The underlying storage is now a valid Max-Heap. Even if the array looks like `[6, 4, 5]` or `[6, 5, 4]` internally, the contract of the priority queue is that `top()` will always return the maximum.
        
          
        
    4. **The Extraction Process:**
        
          
        - Call 1: `pq3.top()` sees the root of the heap $\rightarrow$ `6`. Then `pq3.pop()` removes it and the heap "bubbles up" the next largest value.
            
              
            
        - Call 2: `pq3.top()` now sees the new root $\rightarrow$ `5`. Then `pq3.pop()` removes it.
            
              
            
        - Call 3: Only one element is left $\rightarrow$ `4`.
            
              
            
- **Final Output:** `6 5 4`
    
      
    

## Summary Table for E4

|**Queue**|**Comparator**|**Heap Type**|**Logic**|**Output**|
|---|---|---|---|---|
|**`pq1`**|`std::less` (default)|Max-Heap|Largest first|`3 2 1`|
|**`pq2`**|`std::greater`|Min-Heap|Smallest first|`1 2 3`|
|**`pq3`**|`std::less` (default)|Max-Heap|Largest first (from range)|`6 5 4`|

> **Instructor aside:** Range construction (like in `pq3`) is significantly more efficient than calling `push()` $n$ times. Calling `push()` $n$ times takes $O(n \log n)$ time, while range construction (`make_heap`) takes only $O(n)$ time.

### X3: Explain the Cost (Sorted Array Insertion)

- **Question:** Why is inserting into a sorted array still $O(n)$ even after an $O(\log n)$ binary search?
    
      
    
- **Answer:** Binary search only finds the index where the new element should go. However, an array is a contiguous block of memory. To insert the element at that index, you must shift every subsequent element one position to the right to create a hole. This shifting process takes $O(n)$ time.

# Circular deque :
This code implements a **Circular Deque** (Double-Ended Queue). A deque is a data structure where you can add or remove elements from both the front and the back.

To understand this code, you first need to understand the three key variables being used:

1. **data[]**: The array where the numbers are stored.
    
2. **first**: The index of the element currently at the front.
    
3. **count**: How many elements are currently in the deque.
    
4. **CAPACITY**: The maximum size (which is 8 in your code).
    

The "Circular" part means that if an index goes past the end of the array, it wraps around to the beginning (and vice versa) using the **Modulo Operator (%)**.

---

### 1. push_front(int value)

**How it works:**  
It adds an element to the beginning. To do this, it must move the first index **backward** by one. If first is at index 0, it wraps around to the end of the array (index 7).

- **Logic:** (first - 1 + CAPACITY) % CAPACITY calculates the new index.
    
- **Example:**
    
    - Suppose CAPACITY = 8, first = 0, count = 1.
        
    - You call push_front(10).
        
    - New index: (0 - 1 + 8) % 8 = 7.
        
    - data[7] becomes 10. first becomes 7. count becomes 2.
        

### 2. push_back(int value)

**How it works:**  
It adds an element to the end. The "back" of the queue is logically located at first + count.

- **Logic:** (first + count) % CAPACITY finds the empty slot right after the last element.
    
- **Example:**
    
    - Suppose first = 7, count = 1.
        
    - You call push_back(20).
        
    - New index: (7 + 1) % 8 = 0.
        
    - data[0] becomes 20. count becomes 2.
        

### 3. pop_front(int& value)

**How it works:**  
It removes the first element and "returns" it via the reference variable value. It then moves the first index **forward** by one.

- **Logic:** (first + 1) % CAPACITY moves the start point to the next element.
    
- **Example:**
    
    - Suppose first = 7, count = 2.
        
    - value gets data[7].
        
    - first becomes (7 + 1) % 8 = 0. count becomes 1.
        

### 4. pop_back(int& value)

**How it works:**  
It removes the last element. Unlike pop_front, we don't need to move the first pointer; we just decrease the count.

- **Logic:** The last element is at (first + count - 1) % CAPACITY.
    
- **Example:**
    
    - Suppose first = 0, count = 2.
        
    - The last element is at (0 + 2 - 1) % 8 = 1.
        
    - value gets data[1]. count becomes 1.
        

### 5. front(int& value)

**How it works:**  
This is a "peek" function. It tells you what is at the front without removing it.

- **Logic:** Simply look at data[first].
    
- **Example:**
    
    - If first = 7, value becomes data[7]. count remains the same.
        

### 6. back(int& value)

**How it works:**  
Another "peek" function. It tells you what is at the back without removing it.

- **Logic:** Calculate the last index: (first + count - 1) % CAPACITY.
    
- **Example:**
    
    - If first = 0 and count = 3, the back is at index (0 + 3 - 1) = 2. value becomes data[2].
        

### 7. clear()

**How it works:**  
It logically empties the deque. It doesn't actually erase the numbers in the array; it just sets count = 0. Because all other functions check if (count == 0), the deque now behaves as if it is empty.
