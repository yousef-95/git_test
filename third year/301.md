# graph-traversals-long :
### **1. Using an Adjacency List (The "Fast" way)**

An adjacency list is like a contact list on your phone. For every person (vertex), you have a list of only the people they are actually connected to.

- **How it works:** When the algorithm asks, "Who are the neighbors of vertex V?", the computer only looks at the small list of neighbors for V.
    
- **Speed (Time Complexity):** It is very fast. The total time is **O(V+E)** , where V is the number of vertices and E is the number of edges.
    
- **When to use it:** When the graph is "sparse" (meaning most nodes are NOT connected to each other).
    

### **2. Using an Adjacency Matrix (The "Slower" way)**

An adjacency matrix is like a big grid (a table). Every possible connection is listed, with a 1 if there is an edge and a 0 if there isn't.

- **How it works:** When the algorithm asks, "Who are the neighbors of vertex V?", the computer must scan the **entire row** for vertex V (all V columns) just to find who the neighbors are, even if V only has one neighbor.
    
- **Speed (Time Complexity):** It is slower. The total time is **O(V^2)** .
    
- **When to use it:** When the graph is "dense" (meaning almost every node is connected to every other node).
    

---

### **Comparison Summary**

|                       |                                        |                                   |
| --------------------- | -------------------------------------- | --------------------------------- |
| Feature               | Adjacency List                         | Adjacency Matrix                  |
| **What is it?**       | A list of neighbors for each node.     | A 2D grid of 1s and 0s.           |
| **Finding Neighbors** | Fast (only looks at actual neighbors). | Slower (must scan the whole row). |
| **BFT Running Time**  | **O(V+E)**                             | **O(V^2)**                        |
| **Best for...**       | Sparse graphs (few edges).             | Dense graphs (many edges).        |


These exercises are all about Time Complexity (how long the computer takes to
run the code).

To understand these, remember two symbols:

  - V = Number of Vertices (the circles/nodes).
  - E = Number of Edges (the lines connecting them).

Exercise #1: Adjacency List + Connected Graph

The Scenario: The graph is undirected, connected, and uses an Adjacency List.

  - The Logic:
    1.  Initialization: Setting up the arrays (marked, parent, dist) takes O(V)
        time because we do it once for every vertex.
    2.  The Process: In an adjacency list, we only visit the actual neighbors of
        a node. Over the whole process, we visit every vertex once and every
        edge exactly twice (once from each end). This takes O(E) time.
    3.  Total: O(V + E).
  - The "Trick": The slide says the graph is connected. In a connected graph,
    the number of edges (E) is always at least V-1. Because E is "bigger" or
    equal to V, we can simplify O(V + E) to just O(E).
  - Correct Answer: D. O(E)

Exercise #2: Adjacency Matrix + Connected Graph

The Scenario: The graph is undirected, connected, and uses an Adjacency Matrix.

  - The Logic:
    1.  Initialization: Still takes O(V).
    2.  The Process: Here is the problem: To find the neighbors of a vertex in a
        matrix, the computer cannot just look at a small list. It must check the
        entire row for that vertex to see who has a 1 and who has a 0.
    3.  Since there are V vertices and we must check V columns for each one, the
        math is V \times V.
    4.  Total: O(V^2).
  - Correct Answer: A. O(V^2)

Exercise #3: Adjacency List + ANY Graph (Not necessarily connected)

The Scenario: The graph is undirected and uses an Adjacency List, but we don't
know if it is connected.

  - The Logic:
      - Best Case: Imagine the source vertex is completely alone (isolated). The
        computer initializes the arrays (O(V)), sees the queue is empty, and
        stops. Total time: O(V).
      - Worst Case: Imagine the graph is strongly connected. The computer visits
        every vertex and every edge. Total time: O(E).
  - Conclusion: Because the time changes depending on how the graph is shaped
    (isolated vs. connected), we cannot give one single answer.
  - Correct Answer: E. It depends

Exercise #4: The General Rule (Any Graph + Adjacency List)

The Scenario: Any source, any graph type, using an Adjacency List.

  - The Logic: This is the "universal" answer for BFT using a list.
    1.  You always have to initialize the arrays, which costs O(V).
    2.  You visit the edges that are reachable, which costs O(E).
    3.  Since you must do both, the total time is the sum of both.
  - Why not just O(E)? Because if the graph has 0 edges, you still spent O(V)
    time initializing the arrays.
  - Why not O(V^2)? Because we are using a list, not a matrix.
  - Correct Answer: C. O(E + V)
